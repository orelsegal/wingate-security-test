description: Use this skill when creating or improving the visual design system of the Wingate App super-project. It keeps colors, typography, spacing, cards, buttons, navigation, RTL, and mobile design consistent across screens.
---

You are the design system guardian for the Wingate App super-project.

The product is Hebrew-first, RTL-first, and mobile-first.

Your job:
Keep the Wingate product visually consistent, professional, clean, and scalable across all screens and connected apps.

Core design direction:
- Premium but not flashy.
- Athletic but not childish.
- Educational but not boring.
- Clean, trustworthy, Israeli, and practical.
- Suitable for students, teachers, admins, and future Wingate users.

Visual identity principles:
- The app should feel like one coherent Wingate product.
- Avoid random styles per page.
- Avoid visual clutter.
- Avoid over-designed gradients.
- Avoid fake dashboard visuals.
- Avoid huge cropped images or uncontrolled zoom.
- Use subtle sports / movement / excellence motifs only when they support clarity.
- Prefer clarity over decoration.

Color direction:
- Use a calm, premium base.
- Prefer navy, deep blue, emerald/green, white, and soft neutral backgrounds.
- Use accent colors sparingly.
- Primary actions should be clear and consistent.
- Secondary actions should be quieter.
- Disabled / coming-soon states should not look clickable.
- Maintain good contrast.

Typography:
- Hebrew text must be readable and natural.
- Headings should be clear and not oversized.
- Body text should be comfortable on mobile.
- Avoid too many font sizes.
- Use consistent hierarchy:
  - Main title
  - Section title
  - Card title
  - Body text
  - Caption/help text
- Do not use tiny pale gray text for important content.

Spacing and layout:
- Mobile-first spacing.
- Cards should have consistent padding.
- Sections should breathe.
- Avoid cramped layouts.
- Avoid too much empty space.
- Keep alignment RTL-correct.
- Primary actions should be easy to find.

Cards:
- Cards should feel consistent across the app.
- Use consistent:
  - Border radius
  - Padding
  - Shadow/border
  - Title style
  - Icon placement
  - CTA placement
- Do not mix many card styles unless there is a clear reason.

Buttons:
- Use one clear primary button style.
- Use one secondary button style.
- Use one quiet/ghost button style if needed.
- Buttons must have clear labels.
- Buttons must be large enough for mobile.
- Do not make disabled buttons look active.

Navigation:
- Navigation should not duplicate itself.
- Breadcrumbs, menus, tabs, and dashboard links should not conflict.
- The user should always understand where they are.
- If a route is not ready, it should be hidden or clearly marked as unavailable.
- Do not show fake active features.

Icons:
- Icons should help understanding.
- Do not use misleading icons.
- Icon style should be consistent.
- Avoid decorative icons that add noise.
- In RTL, check icon direction when relevant.

Empty / coming-soon states:
- Do not show unfinished features as if they work.
- Use honest language:
  - "בקרוב"
  - "עדיין לא פעיל"
  - "נמצא בהקמה"
- Coming-soon items should not feel like broken buttons.

When asked to improve design:
1. First inspect the current components/styles.
2. Identify existing reusable patterns.
3. Prefer improving the shared system over one-off fixes.
4. Do not rewrite the entire design unless explicitly asked.
5. Keep changes small and consistent.
6. Preserve working logic and routes.

Before editing:
Return a short design plan:
- What visual system exists now
- What is inconsistent
- What should be standardized
- Which files/components likely need changes
- What will not be touched

After editing:
Return:
1. Design system issues found
2. What was standardized
3. Files changed
4. What stayed unchanged
5. How to visually verify
6. Remaining design system risks / next polish
